# Statement of Work (SoW)
## Tour Request System - туристік агенттік клиенттерінің өтінімдерін басқару жүйесі

**Құжат мәртебесі:** оқу жобасына арналған келісу жобасы (бекітілмеген)  
**Нұсқа:** 1.0  
**Күні:** 19.10.2026  
**Тараптар:** Тапсырыс беруші - туристік агенттіктің уәкілетті өкілі (нақты атауы келісу кезінде толтырылады); Орындаушы — Tour Request System жобалық командасы (4 адам).  
**Негіз:** оқу жобасының бекітілген бэклогы, WBS, НФТ және қабылдау критерийлері. Құжатта көрсетілген нақты мерзімдер мен міндеттемелер тараптармен бөлек бекітілуі тиіс.

## 1. Жұмыстың пәні мен мақсаты
Орындаушы туристік агенттік клиенттерінің өтінімдерін бір жерде тіркеуге, қарауға, мәртебесін өзгертуге және өңдеу барысын бақылауға арналған Tour Request System жүйесінің оқу MVP-нұсқасын дайындайды. Мақсат — өтінімдерді қолмен бақылаудан туатын қателер мен ақпараттың жоғалу қаупін азайту.

## 2. Тапсырылатын нәтижелер (deliverables)
| Код | Нәтиже | Қабылдау дәлелі |
|---|---|---|
| D1 | Өтінімді тіркеу және міндетті өрістерді тексеру | Дұрыс мәліметпен өтінім сақталады; қате енгізілгенде түсінікті хабарлама шығады |
| D2 | Өтінімдер тізімі және жеке карточкасы | Рұқсат етілген пайдаланушы өтінімді тауып, мәліметтерін көре алады |
| D3 | Өтінім мәртебесін өзгерту | Мәртебе рұқсат етілген ережемен өзгереді және сақталады |
| D4 | Пайдаланушыны сәйкестендіру және рөлдік қолжетімділік | Рұқсатсыз пайдаланушы қорғалған әрекеттерді орындай алмайды; іске асыру деңгейі тестпен расталады |
| D5 | Техникалық құжаттама және демонстрация | README, іске қосу нұсқаулығы, тест нәтижелері және демонстрация сілтемесі ұсынылады |

**Ескерту:** D1–D5 - SoW үшін ұсынылған MVP шекарасы. Егер бекітілген бэклогта басқа шекара көрсетілсе, осы тізім сол бэклогқа сәйкестендіріледі. Құжат функциялардың қазіргі уақытта іске асқанын растамайды.

## 3. Жұмыс көлемінің шекаралары
### 3.1 Кіреді (In Scope)
- Өтінім құру, тексеру, сақтау және қарау.
- Өтінім мәртебелерін басқару.
- Менеджердің негізгі жұмыс интерфейсі.
- Пайдаланушылардың рөлдері мен рұқсаттарын жобалау және MVP аясында тексеру.
- Негізгі функционалдық тесттер, қауіпсіздік талаптарын құжаттау, іске қосу нұсқаулығы.

### 3.2 Кірмейді (Out of Scope)
- Онлайн төлем қабылдау және банк жүйелерімен интеграция.
- Әуе билеттерін немесе қонақүйлерді нақты уақыт режимінде брондау.
- Туроператорлардың сыртқы API жүйелерімен өндірістік интеграция.
- Мобильді қосымшаның бөлек Android/iOS нұсқасы.
- Жаппай деректер миграциясы, тәулік бойғы қолдау, коммерциялық өндірістік SLA.

## 4. Қабылдау тәртібі
1. Орындаушы әр нәтижені тестілеуге жарамды ортада көрсетеді және тексеру сценарийін береді.
2. Тапсырыс беруші ұсынылған нәтижені **5 жұмыс күні ішінде** қарайды (ұсынылатын мерзім, келісуді талап етеді).
3. Қабылдау өлшемдері: келісілген сценарийдің орындалуы, маңызды ақаулардың болмауы, қолжетімділік құқықтарының тексерілуі, құжаттаманың берілуі.
4. Сәйкессіздік анықталса, тапсырыс беруші нақты қадамдарымен және күтілетін нәтижесімен жазбаша ескерту жібереді.
5. Орындаушы ескертулерді тіркеп, басымдық пен түзету мерзімін келіседі; қайта тексеру жүргізіледі.
6. Қабылдау тек жазбаша растаумен (мысалы, GitHub Issue/хаттама) рәсімделеді; үнсіз қалу автоматты қабылдау болып саналмайды.

## 5. Өзгерістерді басқару (Change Control)
1. Жаңа талап GitHub Issue түрінде тіркеледі: сипаттама, бизнес-негіздеме, қабылдау критерийлері.
2. PM/BA, Backend, Frontend және QA/DevOps өзгерістің көлемге, мерзімге, тәуекелге және тестке әсерін бағалайды.
3. **Егер соңғы мерзім өзгермесе**, жаңа жұмыс тек бэклогтан **салыстырмалы еңбек сыйымдылығындағы басқа жұмысты алып тастау немесе кейінге қалдыру** арқылы енгізіледі.
4. Тапсырыс беруші қандай функция қосылып, қандай функция шығарылатынын жазбаша мақұлдайды.
5. Мақұлданған шешім бэклогта, WBS/релиз жоспарында және қажет болса SoW жаңа нұсқасында тіркеледі.
6. Мақұлданбаған сұрау бастапқы міндеттемелерге кірмейді.

**Мысал:** егер тапсырыс беруші жаңа SMS-хабарлама функциясын сұраса, команда оның еңбек сыйымдылығын есептейді. Мерзім өзгермейтін болса, көлемі ұқсас басқа функцияны кейінге қалдыру жөнінде келісім қажет.

## 6. Тапсырыс берушінің міндеттері
- Бизнес-талаптарды және қабылдау критерийлерін уақытында нақтылау.
- Өтінім мәртебелері мен рөлдеріне қатысты шешім қабылдайтын өкілді белгілеу.
- Демонстрация мен қабылдауға қатысу; ұсынылатын жауап беру мерзімі — 5 жұмыс күні.
- Тестілеуге арналған жасанды немесе анонимдендірілген мысал деректерін ұсыну.
- Қажет өзгерістерді жазбаша бекіту.

## 7. Орындаушының міндеттері
- Бекітілген көлем аясында нәтижелерді дайындау және тестілеу.
- Репозиторийде код, құжаттама және өзгерістер тарихын сақтау.
- Маңызды тәуекелдер мен кедергілер туралы PM арқылы хабарлау.
- Клиенттердің нақты дербес деректерін оқу/демонстрациялық ортаға рұқсатсыз жүктемеу.
- Қабылдау кезінде анықталған келісілген көлемдегі ақауларды келісілген мерзімде қарастыру.

## 8. Нәтижеге құқықтар
Оқу жобасының бастапқы коды, құжаттамасы және демонстрациялық материалдарына құқық беру тәртібі **тараптар мен оқу орнының қолданыстағы ережелеріне сәйкес бөлек келісіледі**. Үшінші тарап кітапханалары өз лицензияларына бағынады. Бұл SoW құқықтарды автоматты түрде бермейді.

## 9. Міндеттеме болып саналмайтын жұмыстар
- Қабылдаудан кейін мерзімсіз тегін техникалық қолдау.
- Бастапқы көлемнен тыс жаңа функциялар мен интеграциялар.
- Жүйеде ешқашан ақау болмайтынына абсолют кепілдік.
- Нақты өндірістік инфрақұрылымға орналастыру, 24/7 мониторинг немесе ақылы бұлт қызметтері.
- Заңдық сәйкестік туралы ресми сертификат немесе тәуелсіз аудит қорытындысы.

Бұл жұмыстар тек жеке келісім, ресурс және мерзім бекітілсе ғана орындалады.

## 10. Шектеулер мен болжамдар
- Жоба төрт адамдық оқу командасымен және бекітілген семестрлік мерзім аясында орындалады.
- Нақты пайдаланушылар саны, өндірістік жүктеме және ақылы инфрақұрылым шығындары кейінгі бюджет есебінде **болжам ретінде** көрсетіледі.
- Қолданылатын технологиялар бекітілген архитектуралық шешімдерге сәйкес нақтыланады.
- Дербес деректерді Қазақстан аумағында сақтау және өңдеу бойынша қолданылатын талаптар өндірістік енгізу алдында бөлек тексеріледі.
- SoW-дағы ұсынылған мерзімдер мен көрсеткіштер нақты келісімге дейін шарттық міндеттеме емес.

## 11. Басқару және коммуникация
- **PM/BA:** талаптар, тапсырыс берушімен байланыс, өзгерістерді келісу.
- **Backend:** серверлік логика, деректерге қолжетімділік және API.
- **Frontend:** пайдаланушы интерфейсі және клиенттік тексерулер.
- **QA/DevOps:** тестілеу, тексеру нәтижелері, жеткізу процесі.
- Бэклог пен шешімдер GitHub Issues/Projects және репозиторий құжаттарында тіркеледі.
